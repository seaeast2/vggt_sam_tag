# VGGT-Ω 잔차 깊이 보정: 평면 방향과 다중시점 관측의 통제 실험

## 1. 목표와 검증 가설

**원본 깊이를 평면화하는 효과와, 관측을 이용해 평면 방향을 바로잡는 효과를 분리한다.**

이전 실험에서 육안 품질과 GT 정확도가 상충한 원인은 아직 확정하지 않는다. 다음 가설을 각각 검증한다.

- **H1 — 평면화:** raw 깊이에 맞춘 평면으로 투영하면 표면 두께는 감소하지만, 방향 오류 때문에 GT 깊이 오차는 증가할 수 있다.
- **H2 — 방향 보정:** 동일 평면의 다중시점 대응으로 방향과 거리를 추정하면, raw 평면 방향을 유지한 보정보다 방향·깊이 오차가 감소한다.
- **H3 — 관측 지원:** 방향 보정의 성패는 대응점 개수뿐 아니라 시차·공간 분포·매칭 오류에 영향을 받는다.

첫 실험은 **제공 카메라 보정과 사람이 확인한 평면 마스크**를 사용한다. SAM 자동 분할, 카메라 자세 최적화, 장기 SLAM, 루프 폐쇄는 이후 단계로 분리한다. 깊이·법선·보정량을 예측하는 추가 신경망은 사용하지 않는다.

## 2. 데이터와 입력 통제

### 평가 데이터

| 데이터셋 | 사용 범위 | 초기 깊이 | 역할 |
|---|---|---|---|
| Middlebury v3 Stereo | 공개 GT가 있는 training 15쌍, quarter 해상도 | VGGT-Ω | 실내 평면·양안 관측 |
| KITTI 2015 Stereo | 공개 training 중 ID 000000–000019의 기준 시각 좌·우쌍 | VGGT-Ω | 도로·건물 평면과 거리 영향 |
| ETH3D 고해상도 MVS | office, pipes, delivery area, courtyard | VGGT-Ω | 다중시점·무텍스처 영역 |

세 데이터셋 모두 공개 GT를 제공하므로 이번 실험 대상으로 유지한다. SGM/BM·기존 MVS 깊이는 이번 비교군에 넣지 않는다. 공개 training 자료를 **로컬 평가셋**으로 사용하며 공식 hidden test 성능으로 표현하지 않는다. Middlebury에는 잔여 수직 시차가 있으므로 대응점을 동일 행으로 강제하지 않는다. [Middlebury 구성](https://vision.middlebury.edu/stereo/submit3/), [KITTI 구성](https://www.cvlibs.net/datasets/kitti/eval_scene_flow.php?benchmark=stereo)

GT는 센서 기반 GT로 통칭하되 측정 출처를 구분한다. Middlebury는 구조광 기반 시차, KITTI 2015는 레이저 스캔과 동적 차량 CAD 모델 등을 결합한 GT, ETH3D는 FARO 레이저 스캔 기반 점군·깊이를 사용한다. 세 데이터셋을 모두 순수 LiDAR 직접 관측으로 표시하지 않는다.

- 개발: Middlebury Adirondack·ArtL·Jadeplant, KITTI 000000–000004, ETH3D office·pipes.
- 고정 평가: 나머지 Middlebury 12쌍, KITTI 000005–000019, ETH3D delivery area·courtyard.
- 이전에 사용한 office·pipes는 독립적인 새 장면 검증으로 취급하지 않는다.
- 평면이 없거나 지원이 부족한 샘플도 제외 목록에 남긴다. 결과를 보고 좋은 샘플로 교체하지 않는다.

### 영상·카메라·GT

- VGGT-Ω checkpoint, 소스 revision, 입력 전처리와 공동 추론 이미지 목록을 고정한다. 초기 긴 변은 512픽셀로 두고 실제 모델 전처리 결과를 기록한다.
- Stereo는 좌·우 두 장을 공동 추론한다.
- ETH3D는 카메라 중심 간 거리의 중앙값에서 가장 가까운 이미지를 시작점으로, 거리 기준 farthest-point 방식으로 총 5장을 선택한다. 동률은 이미지 ID로 결정한다. 선택에 GT나 보정 성능을 사용하지 않는다.
- 최적화에는 제공된 K·상대 자세를 고정 사용한다. 이는 **카메라 오차를 통제한 조건의 실험**이며 실제 SLAM 조건과 구분한다.
- 원본 이미지→처리 이미지 좌표 변환, K, depth, mask를 같은 격자로 맞춘다.
- ETH3D는 undistorted RGB와 원본 GT depth 격자의 대응을 공식 카메라 모델로 검증한다. GT 결측을 보간해 채우지 않는다. [ETH3D 규약](https://www.eth3d.net/documentation)

### 평면 마스크와 대응점

- GT·raw 깊이·최종 pointmap을 보지 않고 RGB에서 **동일한 물리 평면**을 수동 지정한다. 서로 다른 벽, 가림 물체, 경계는 분리한다.
- 이미지마다 최대 3개 평면을 RGB 면적순으로 선택한다. 벽·바닥 외에도 명확한 책상·문 등은 허용하되 종류를 기록한다.
- SIFT 대응을 양방향 일치와 ratio 0.75로 생성하고, 제공 카메라 기하에 대한 1픽셀 이하 epipolar 오차로 거른다. 전체 track과 대응 overlay를 보존한다.
- track ID와 seed 0으로 FIT/보류를 70/30 분리한다. 같은 track의 모든 관측은 같은 split에 둔다.
- 평면별 FIT 12개·보류 6개 이상, FIT 대응의 영상 convex hull이 평면 마스크 면적의 10% 이상일 때 주 최적화를 수행한다. 부족한 경우 `INSUFFICIENT_SUPPORT`로 보존한다.
- 시차·삼각측량 각도·양의 깊이 비율을 기록한다. 중앙 삼각측량 각도 1° 미만은 저시차 진단군으로 분리한다.

## 3. 보정 방법과 비교군

### 원본·잔차 관리

VGGT 원본 깊이 $D_i^0$, confidence, 예측 K·pose를 변경 없이 저장한다.

알려진 카메라 이동의 스케일과 VGGT 깊이의 스케일을 맞추기 위해, **FIT RGB 대응을 삼각측량한 깊이만으로 이미지 묶음당 양의 scale $s$ 하나**를 구한다. 프레임별 scale·shift는 허용하지 않는다. 이 값은 모든 비교군에 공통 적용하고 GT를 사용하지 않는다.

$$
D_i^{base}=sD_i^0,\qquad D_i^{corr}=D_i^{base}+\Delta D_i
$$

scale은 잔차에 섞지 않고 별도 저장한다. 보정하지 않은 영역은 $\Delta D=0$이다. 기본 비교군은 원본 depth를 제공 카메라 광선에 놓은 **통제 기준선**이며, VGGT 예측 K·pose까지 사용한 원본 산출물과 구분한다.

### 평면 표현과 목적함수

평면은 기준 카메라에서 $\mathbf p=\mathbf n/e$로 표현하고, 다른 프레임에는 같은 물리 평면을 좌표 변환해 사용한다.

$$
D(u,v)=-\frac{1}{\mathbf p^\top K^{-1}[u,v,1]^\top}
$$

주 목적함수는 **FIT 대응점의 양방향 재투영 오차에 대한 Huber 손실**로 한다. Huber 기준은 처리 이미지 1픽셀이다.

- RGB 광도 손실, raw 법선 prior, Manhattan 직교 제약은 주 실험에서 사용하지 않는다.
- raw 깊이는 초기화와 비교군 생성에 사용한다.
- 각 이미지의 평면에서 대응점을 역투영하고 상대 자세로 다른 이미지에 투영한다.
- 고정된 FIT 관측을 사용하며, 최적화 도중 불리한 잔차를 삭제하지 않는다.
- 수용 마스크 전체에서 유한한 양의 깊이를 요구한다.
- raw 평면 초기값과 FIT 호모그래피 기반 초기값을 사용한다. 사용 가능한 해 중 FIT 목적함수가 낮은 것을 선택하며 보류·GT로 선택하지 않는다.
- 해가 퇴화하거나 수치 검증에 실패하면 원본을 유지하고 제안값·실패 이유를 보존한다.

### 비교군

| 군 | 방향 | 거리 | 검증 목적 |
|---|---|---|---|
| **B0 원본** | raw 그대로 | raw 그대로 | 공통 기준선 |
| **B1 raw 평면 투영** | raw 깊이의 robust 평면 적합 | 같은 적합값 | 평면화만으로 생기는 변화 |
| **B2 방향 고정 보정** | B1 방향 고정 | 대응점으로 최적화 | 거리 수정 효과 |
| **B3 방향·거리 보정** | 대응점으로 최적화 | 대응점으로 최적화 | 방향 자유도의 추가 효과 |

B1–B3는 **같은 평면 소속·관측·카메라·scale**을 사용한다. 초기 평면 적합은 법선 평균 대신 raw 역투영점의 robust 평면 적합을 사용한다.

출력에는 `raw depth`, `scale`, `residual depth`, `corrected depth`, 유효 마스크, 평면 계수·좌표계·관측 ID·solver 상태를 연결해 저장한다. pointmap은 이 값에서 파생하며 별도 최적화하지 않는다.

## 4. 실행 단계와 평가

### 단계별 실행

| 단계 | 작업 | 다음 단계 조건 |
|---|---|---|
| **P0 기하 검증** | 합성 평면·카메라·정확한 대응으로 방향 복원, 광선 교차·좌표 변환·미분 검증 | 알려진 평면 복원 통과 |
| **P1 입력 동결** | 데이터·마스크·track split·VGGT 캐시·카메라 격자 확인 | 입력과 지원 상태 확정 |
| **P2 개발 실험** | 개발 장면에서 B0–B3 비교, solver·설정 확정 | 설정 파일·코드 hash 동결 |
| **P3 고정 평가** | 설정 변경 없이 평가 장면 전체 실행 | 실패·미지원 포함 출력 보존 |
| **P4 원인 분석** | 방향·거리·평면성·깊이 정확도·육안 품질의 관계 분석 | 가설별 결론 작성 |

### 필수 평가

- **방향:** GT 유효점으로 적합한 참조 평면과의 법선 각도 오차. GT 참조 평면의 잔차·지지 면적·bootstrap 불확실성도 함께 보고한다. 참조 방향이 불확실하면 방향 판정은 보류한다.
- **위치·깊이:** 평면 영역 camera-Z MAE·RMSE·AbsRel, GT 참조 평면까지의 거리.
- **평면성:** 보정 전후 표면 두께와 평면 잔차. 강제 평면화 후 잔차 0은 정확도 증거로 사용하지 않는다.
- **관측 일반화:** 최적화에 쓰지 않은 track의 재투영 오차.
- **영역 보존:** 마스크 밖 depth·RGB·관측 ID 불변, 깊이 양수·자기 투영 일치.
- **정성 비교:** 동일 시점·축·색 범위의 depth 오차맵, 잔차맵, 벽 단면, 법선, pointmap. GT 결측은 별도 표시한다.

GT 평면 적합은 **평가 전용**이며 solver·마스크·초기화·모델 선택에 전달하지 않는다. GT 평면에 잘 맞지 않는 영역도 결과에서 삭제하지 않고 평면 가정 위반으로 보고한다.

### 성공·실패 판정

- P0의 무잡음 합성 조건에서는 법선 오차 0.1° 미만, 상대 깊이 오차 0.1% 미만을 기술 통과 기준으로 둔다. 순수 회전·공선 대응·매칭 이상치도 검사한다.
- 주 비교는 **B3 대 B2**로 한다. 평면별 paired 변화와 장면별 집계, 장면 단위 bootstrap 95% 구간을 보고한다. 픽셀을 독립 샘플로 세지 않는다.
- 방향 오차와 깊이 MAE가 함께 감소하고 보류 재투영 오차가 악화되지 않을 때 해당 장면의 방향 보정 효과를 인정한다.
- B1에서 두께는 줄지만 방향·GT 오차가 증가하면 H1을 지지하는 사례로 기록한다.
- 방향만 개선되거나 관측 손실만 감소하면 부분 결과로 남긴다. 통계적 불확실성이 크면 `INCONCLUSIVE`로 판정한다.
- 모든 데이터셋 결과를 별도로 보고하고 단위가 다른 오차를 하나의 평균으로 합치지 않는다.

## 5. 후속 단계와 가정

- 첫 실험의 목적은 **평면 방향 오류 가설 검증**이다. 장기 SLAM 성능 향상이나 자동 시스템의 신규성을 주장하지 않는다.
- P0–P4 후 설정을 새로 동결하고, 수동 마스크→SAM, 제공 자세→추정 자세, 고정 이미지 묶음→시간적 누적 순서로 한 요인씩 교체한다.
- 장기 SLAM·루프 폐쇄는 별도 시퀀스와 평가 계획을 마련한다. Stereo 쌍과 ETH3D 고해상도 MVS만으로 장기간 운용을 검증하지 않는다.
- 8GB VRAM에서는 VGGT·분할 추론과 CPU 기하 최적화를 분리한다. 실제 메모리 가능 여부는 P1에서 확인하고, OOM 시 실패를 보존한 뒤 개발 단계에서 공통 입력 크기를 재확정한다.
- 기존 저장소 결과는 읽기 전용 기준 자료로 유지한다. 새 실행은 단계·run별로 격리하며 원본·제안·선택 결과와 코드·설정·데이터 hash를 함께 보존한다.

## 6. 실험 코드·폴더 분리와 결과 보존

이번 실험의 고유 계열명은 `planar_residual_depth`로 고정한다. 단계 코드는 위의 **P0–P4**, 비교군 코드는 **B0–B3**를 사용한다. 이전 저장소의 같은 단계 문자와 혼동하지 않도록 경로와 manifest에는 항상 계열명을 함께 기록한다.

실행 ID는 `{dataset}-{sample}-{stage}-{YYYYMMDD}-{seq}`로 한다. `seq`는 같은 날짜·샘플·단계에서 001부터 증가시키며, 재실행도 새 ID를 부여한다. 예: `eth3d-office-P2-20261117-001`.

```text
experiments/planar_residual_depth/
  common/                         # 공통 입출력·기하·평가 도구
  P0/ ... P4/                     # 단계별 실행 코드
  configs/                        # 개발·동결 설정

data/planar_residual_depth/
  middlebury/ kitti2015/ eth3d/    # 원본 데이터·보정·GT; 읽기 전용 입력

results/planar_residual_depth/
  {run_id}/
    manifest.json                 # 계열·단계·상태·입력·parent run·hash
    config_resolved.json
    environment.json
    source/                       # 해당 실행 코드·설정 snapshot
    logs/
    artifacts/
      inputs/                     # 입력 목록·좌표 변환·mask·track split
      raw/                        # 불변 원본 depth와 모델 출력
      calibration/                # 제공 K/pose·공통 scale·출처
      arms/B0/ ... B3/             # 군별 잔차·깊이·평면·pointmap·solver 상태
    evaluation/                   # 군별 수치·GT mask·방향 불확실성
    figures/                      # 동일 조건 비교·오차맵·단면

docs/experiments/planar_residual_depth/
  index.md                        # 전체 실행·판정·canonical 결과 색인
  P0/ ... P4/
    {run_id}/report.md             # 실행별 입력·방법·결과·제한
```

- 단계 실행은 자신의 run 폴더에만 출력한다. 이전 단계·다른 비교군·기존 실행을 덮어쓰지 않는다. 같은 run ID의 기존 출력이 있으면 새 실행을 거절한다.
- 후속 단계는 명시한 parent run의 입력을 읽으며, 데이터셋별 또는 단계별 전역 `latest` 파일을 암묵적으로 사용하지 않는다. 대형 원본을 중복 복사하지 않을 때도 원본 경로·크기·hash를 manifest에 고정한다.
- B0–B3는 한 run 안에서 별도 폴더로 저장하고 공통 mask·track split·scale·K/pose의 hash를 기록한다. 원본 raw와 baseline을 보정 결과로 갱신하지 않는다.
- 보정 코드에는 GT를 전달하지 않는다. GT는 평가 단계에서 별도로 읽고, 사용한 GT 파일·평가 mask·참조 평면 추정 규약을 기록한다.
- 재실행·실패·중단·OOM·지원 부족 결과도 보존한다. 코드나 설정을 바꾼 실험에는 새 run ID와 변경 이유를 기록한다. 한 요인 변경 보조 실험은 P2a/P2b처럼 구분하고 원래 P2 결과를 대체하지 않는다.
- `proposed`와 실제 사용할 `retained`의 선택을 구분한다. 거절된 제안과 원본 복원 결과를 모두 보존하고 선택 이유를 기록한다.
- canonical 실행은 보고서 색인에서 명시적으로 지정하며 이전 결과를 삭제하거나 이동해 숨기지 않는다. 개발 결과·고정 평가 결과·진단 결과를 구분한다.
- 저장소에는 코드·설정·경량 보고서·산출물 목록과 hash를 보관한다. 원본 데이터·모델·대형 depth/pointmap/PLY 캐시는 별도로 보존하고 버전 관리 대상에서 제외한다.
- 단계 완료 시 코드·설정·source snapshot과 보고서의 run ID 일치, B0 원본 보존, 산출물 존재·hash를 검사한다. 단순 실행 완료와 기술 검증 통과, 실제 정확도 개선 판정을 별도로 보고한다.

## 7. 개발 보조 실험 기록: P2a 안정성

K01 P2 이후 FIT 관측 선택의 민감도를 분리하기 위해 P2a를 추가했다. 동일한 이미지·승인 mask·K/pose·scale·초기 평면·solver·보류21개를 유지하고, FIT47개 track만 seed0으로47회 복원추출하는 반복을30회 수행했다. 각 draw를 B2/B3에 공통 사용한다. 설정은 fit 실행 전에 config_resolved.json으로 저장했고, 전체 fit 저장 후 별도 프로세스로 GT를 평가했다. 이 조건부 bootstrap은 새로운 장면의 일반화 신뢰구간이나 오류 원인 식별 실험이 아니다. 원래 P2 결과를 대체하지 않는다.

실행·수치·한계: [P2a 보고서](experiments/planar_residual_depth/P2a/kitti-000000-P2ae-20261117-001/report.md).

## 8. 개발 보조 진단 기록: P2b 대응점 참조 비교

## 9. 사용자 지시에 따른 영역 검토 변경 및 P3–P4 완료

2026-11-17 사용자가 “이제부터는 나의 영역 검토 없이 계속 진행해줘.”와 “P4 실험까지 한번에 계속 진행해줘.”로 후속 영역 검토 생략과 연속 실행을 지시했다. 원래 사람 검토를 요구한 계획의 해당 조건은 이후 사례에 적용하지 않는다. 기존 K02–K04 사용자 승인 영역과 결과는 보존하고, 새26개는 에이전트가 RGB만 보고 지정한 `AGENT_RGB_DESIGNATED_USER_UNREVIEWED` 영역으로 분리했다. SAM·사용자 승인·GT 평면 마스크로 표현하지 않는다. 모든 신규 영역을 raw/GT 평가 전에 동결하고, 각 장면의 명확한 보수적 유한 평면1개(최대3개 한도 내)를 시도했다. 평면이 불명확하면 제외 사유를 보존했다.

P3: 고정 평가29개(KITTI15/Middlebury12/ETH3D2) 전체 처리. 21개에서 보정·GT 평가,8개는 관측 부족 또는 명확한 평면 부재로 미보정 상태를 보존했다. P4: 동일 영역 paired B3–B2 비교, 데이터셋별 집계, GT 참조 법선의16×16 공간 block bootstrap100회, 장면 ID bootstrap10000회(독립 장면 신뢰구간으로 해석 금지), 평면성·거리·깊이·관측 오차 분석 완료. 기준을 낮추거나 평가 결과로 영역/해를 재선택하지 않았다.

완료는 전체 장면의 정확도 개선이나 ETH3D 보정 성공을 뜻하지 않는다. 기존 세 도로 사례만으로 B2가 항상 낫다는 해석은 전체 고정 평가에서 유지되지 않았다. 최종 결과·악화 사례·제약과 후속 가설은 [P4 최종 보고서](experiments/planar_residual_depth/P4/all-evaluation-P4-20261117-001/report.md)에 기록했다.

## 10. P5a–P8 후속 탐색: 거리·신뢰도와 제한적 방향 갱신

사용자가 제안 목록의 P8까지 실행을 요청해 기존21개 지원 사례에서 P5a 거리별·P5b 픽셀 confidence별·P5c 결합/통제 진단, P6 부분 평면 방향의 전체 전파, P7 두 시점 법선 통합, P8 전체 raw 방향 기준1° 이내 갱신을 실행했다. 기존8개 미지원 사례는 유지했다. P6–P8 규칙을 P5의 GT 진단 전에 고정했고, 원본·mask·FIT/보류·scale·제공 카메라·평면 표현은 유지했다. GPU 추론·학습은 추가하지 않았다.

근거리의 정의는 ROI 내 raw camera-Z 하위1/3이며 GT 거리가 아니다. confidence는 VGGT depth_conf 점수이고 카메라 자세 신뢰도가 아니다. 점 개수 통제와 영상4×4 cell별 공간 통제를 분리했다. near/mid/far 공간 지지를 동시에 맞출 수 없어 거리 자체 효과는 미분리로 남겼다.

P4를 이미 본 뒤의 후속 탐색으로 독립 검증은 아니다. P8까지 모든 계산·평가·감사를 마쳤으며 원본 캐시, confidence, 선택ID·깊이 residual·한도·GT 지표·부모 hash 불변을 확인했다. [P5a–P8 보고서](experiments/planar_residual_depth/P5_P8/all-cases-P5-P8eval-20261117-001/report.md).

## 11. P9a–P9d: 원본 RGB 직접 정렬

사용자 요청으로 기존21개 사례에서 RGB 직접 정렬을 실행했다. P9a는 기존 B2/B3 및 사후 GT 참조 plane의 RGB warp 진단, P9b는 방향 고정·광도 기반 거리 보정, P9c는 방향·거리 공동 광도 보정, P9d는 밝기·텍스처·appearance mismatch 진단이다. GT는 모든 fit/pre-GT 검사 후 평가에서만 사용했다. GT plane warp는 oracle 진단 전용이다.

기존 mask·카메라·scale을 유지하고, RGB Huber+gain/bias·Gaussian coarse-to-fine·양의깊이·B2 기준 warp±3px 범위를 사전에 동결했다. 같은 warp 범위의 기존 feature 목적함수 대조군을 추가했다. 영상 block별 FIT/보류32px·guard8px를 사용하고 현재 residual에 따른 삭제는 하지 않았다. 16개(KITTI13/Middlebury3)에서 RGB 보정,5개에서는 공간 지원 부족으로 B2 유지. 이전8개 미지원은 그대로 보존했다.

RGB 정렬이 대체로 깊이 순위와 연결되지만 예외가 있고, KITTI의 평균 깊이 개선이 평균 법선 개선으로 이어지지는 않았다. 기존에 본 장면의 탐색 결과로 독립 일반화·실제 가림 검출·RGB 경계 재분할·장기 SLAM을 검증한 것으로 표현하지 않는다. [P9 최종 보고서](experiments/planar_residual_depth/P9/all-cases-P9eval-20261117-001/report.md).

## 12. P10: 실내·실외·드론 연속 영상

사용자 요청으로 TUM/KITTI Raw/EuRoC 각 한 구간의 연속20장(약4초)을 확보하고 VGGT-Ω 추론,2/4/8/16 관측 평면 보정,센서 참조 평가,비교 영상을 완료했다. 제공 자세 통제와 모델 추정 K/pose 조건을 분리하고, 모델 자체의 RGB 입력2/4/8/16장 비교도 별도 실행했다. RGB 조건의 scale 정렬은 평가에만 GT 일부를 사용하며 보정에는 GT를 넣지 않았다. 원본 raw와 residual, 모든 실패/후행 마스크 수정 이력을 분리 보존했다.

이는 짧은 오프라인 탐색이며 장기 SLAM은 아니다. 이미지 수 증가 또는 평면 보정이 깊이를 일관되게 개선한다는 증거를 얻지 못했다. [P10 통합 보고서](experiments/planar_residual_depth/P10/three-sequences-P10RGBeval-20261117-001/report.md).
