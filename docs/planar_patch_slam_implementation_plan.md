# 평면 패치 기반 SLAM 검색 구현 계획

## 1. 목표와 시작점

P31에서 깊이 보정에 사용한 유한 평면 패치와 삼각형을 독립적인 지도 산출물로 저장한다. 새 카메라의 예상 시야에 들어오는 패치를 검색하고, 그 패치를 관측한 키프레임과 이미지 영역으로 특징점 매칭 범위를 좁힌다. 목표는 실제 재방문 후보를 유지하면서 키프레임 후보 수와 매칭 시간을 줄이는 것이다.

P31의 `mesh.npz`에는 정점·삼각형과 픽셀 출처가 있고, `observations.npz`에는 피팅과 검증에 사용한 픽셀이 있다. 평면은 프레임별로 추정되므로 지도에 넣기 전에 각 관측을 물리 표면에 연결해야 한다. 복도에서 깊이 MAE 개선은 소폭이었고 Bonn 계단 ROI에서는 악화됐다. 패치 검색의 채택 여부와 보정 깊이의 채택 여부는 각각 평가한다. 검색 실험에서는 원본 깊이를 기준으로 매칭 및 포즈를 검증한다. [P31 실험 기록](experiments/planar_residual_depth/index.md) · [메시 내보내기](../experiments/planar_residual_depth/P31/run.py)

## 2. 패치와 관측 저장

| 항목 | 저장 내용 |
|---|---|
| 패치 | 안정적인 `patch_id`, `submap_id`, 형상 버전, 단위 법선·오프셋, 유한 다각형의 외곽선과 구멍, 연결 성분, 3D 경계 상자, 인접 패치 및 공유 변 |
| 삼각형 | 패치별 정점 배열과 인덱스, 삼각형의 소유 패치 ID. 벽의 같은 평면 위 삼각분할과 실제 모서리에서 꺾이는 인접 평면을 구분 |
| 관측 | `(keyframe_id, observation_id)`, 원본 P31 프레임·패치 ID, 픽셀 ROI 및 유효 마스크, 피팅·검증 픽셀 ID, 관측 방향과 가시 면적, 관련 특징점 및 기술자 참조 |
| 키프레임 | 이미지 식별자, 타임스탬프, 원본과 처리 격자 간 변환, K, 카메라 포즈, 서브맵 좌표 변환, 관측 패치 ID 목록 |
| 갱신 이력 | 병합·분할 전후 ID, 근거 관측, 변환의 버전과 적용 시점. 기존 관측에서 당시 패치를 찾을 수 있는 ID 연결 |

교환 형식은 스키마 버전이 있는 JSON 메타데이터와 NPZ 배열로 시작한다. 폴리곤을 SLAM 밖에서도 읽을 수 있도록 삼각형 메시를 별도로 내보낸다. 패치와 정점은 서브맵 좌표계에 저장하고, 지도 최적화에서 변경된 포즈와 스케일은 서브맵 변환 버전으로 관리한다. 패치 모양이 갱신돼도 관측 ID와 원본 픽셀 인덱스를 보존한다.

P31의 같은 평면에 속하는 래스터 삼각형에서 경계 루프를 추출한다. 구멍과 분리된 성분이 유지되는 범위에서 윤곽을 단순화하고 다시 삼각분할한다. 프레임이 다른 관측은 법선·오프셋, 유한 영역 겹침, 양방향 재투영과 가림 일치가 모두 지지할 때 연결한다. 겹침이 부족한 평행 벽과 계단의 인접 단은 별도 ID로 유지한다.

## 3. 검색 경로

### 포즈 예측이 있는 경우

1. 예상 카메라 포즈와 불확실성으로 시야 범위를 정한다. 드리프트가 커질수록 위치·방향 허용 범위를 넓힌다.
2. 서브맵별 BVH에서 시야와 교차하는 패치 경계 상자를 찾는다. 살아남은 패치는 다각형이나 삼각형 재투영으로 화면 교차와 깊이 순서를 검사한다.
3. 해당 패치의 관측 목록을 모아 키프레임 후보를 만든다. 재투영 겹침, 관측 각도, 가시 면적과 함께 여러 패치가 같은 키프레임을 지지하는지로 순위를 매긴다.
4. 현재 프레임과 후보 키프레임에서 해당 ROI의 특징점을 매칭한다. 동일 프레임에서 특징점을 한 번 검출해 ROI로 제한하는 방식부터 평가한다. ROI 검출 자체의 속도 효과는 별도 측정한다.

### BSP 비교

안정된 서브맵에서 둠의 카메라 쪽 우선 순회와 가지 제외를 응용한 BSP를 구현한다. 분할 평면에 걸친 패치는 같은 패치 ID로 양쪽 가지에서 참조하고 질의 결과에서 중복을 제거한다. 공간 분할이 바뀌면 인덱스만 교체하도록 지도 데이터와 저장 형식을 공유한다. 동일한 시야 질의에 대해 패치 전수 검사, BVH, BSP의 반환 후보·질의 시간·구축 시간·메모리를 비교한다. [둠 BSP 소스](https://github.com/id-Software/DOOM/blob/master/linuxdoom-1.10/r_bsp.c)

### 루프 클로저와 재위치 추정

포즈가 불확실하거나 시야 검색에서 지지가 부족하면 이미지 기반 장소 인식으로 과거 키프레임을 검색한다. 시간상 인접 프레임을 제외하고 상위 후보의 키프레임 포즈 또는 초기 상대 포즈를 가설로 삼아 같은 패치 질의를 수행한다. 반복되는 복도에서는 하나의 벽 평면에 의존하는 대응을 거르고, 문틀·벽 끝·바닥 접합선과 여러 방향의 패치 배치를 함께 검사한다.

패치는 후보 순위와 특징점 검색 범위를 정하는 데 사용한다. 루프 제약은 기존 SLAM의 강건 포즈 추정과 공시야 검증을 통과한 뒤 추가한다. RGB-D처럼 스케일이 정해진 경로는 SE(3), 스케일 정렬이 필요한 단안 서브맵 간 검증은 사용하는 SLAM의 Sim(3) 규약을 따른다. [ORB-SLAM3 장소 인식과 공시야 검증](https://doi.org/10.1109/TRO.2021.3075644)

## 4. 구현 순서

| 단계 | 작업 | 확인 사항 |
|---|---|---|
| 1 | P31 산출물을 읽어 패치·삼각형·관측을 별도로 내보내고 다시 로드한다. | 정점과 색상·픽셀 출처의 왕복 일치, 구멍·분리 성분 보존, 잘못된 참조 검출 |
| 2 | OpenLORIS의 같은 표면을 시점 간 연결하고 패치별 키프레임 관측 인덱스를 구축한다. | 수동 확인한 동일 벽·문틀의 일관성, 평행 벽 오병합, Bonn 계단 단 분리 |
| 3 | 오프라인 시야 질의를 구현한다. 전수 검사와 BVH를 먼저 검증하고 안정된 서브맵에 BSP를 추가한다. | 기준 시야 질의에서 정답 패치 누락률, 검색·구축 시간, 지도 갱신 후 일관성 |
| 4 | 동일한 추출기와 기하 검증으로 전체 이미지와 패치 제한 매칭을 비교한다. 장소 인식 후보와 결합한 조건도 평가한다. | 후보 재현율, 오탐, 인라이어 수와 영상 분포, 상대 포즈 오차, 탐색 실패 시 복구 |
| 5 | 오프라인 비교를 통과하면 SLAM 재생 실험에서 검색 경로를 연결한다. | 루프 정밀도·재현율, ATE·RPE, 추적 손실과 복구, 키프레임 처리 지연 |

## 5. 평가와 채택

- 기존 OpenLORIS 두 구간으로 패치 저장과 포즈 기반 검색을 점검한다. 기존 프레임에 실제 재방문 쌍이 부족하면 더 긴 구간 또는 별도 녹화를 사용한다. 재방문 정답은 참조 포즈와 실제 시야 겹침을 함께 보고 정의한다. Bonn 계단은 경계 보존과 잘못된 패치 병합을 확인하는 데 사용한다.
- 동일 키프레임 쌍에서 전체 이미지 매칭, 패치 ROI 매칭, 장소 인식 후 패치 ROI 매칭을 비교한다. 인덱스 비교에서는 특징점 추출·검증 설정을 고정한다.
- 실제 재방문 후보의 recall@K, 검증된 루프의 정밀도·재현율, 포즈 오차를 기록한다. 키프레임 후보 수·기술자 비교 수와 함께 질의, 특징점 매칭, 포즈 검증, 전체 처리의 p50·p95 시간을 측정한다. 인덱스 구축·갱신과 메모리 비용도 포함한다.
- 포즈의 위치·회전 오차를 단계별로 주입한다. 좁은 시야 검색이 정답을 놓치기 시작하는 조건과 장소 인식 경로로 복구되는 비율을 측정한다. 반복 복도, 가림, 관측이 적은 구간의 실패도 보존한다.
- 개발 구간에서 허용 재현율 손실과 목표 지연을 정하고 별도 평가 구간 전에 고정한다. 기본 검색 경로 채택에는 정답 후보 유지, 오탐 억제, 전체 처리 시간 감소가 필요하다. 루프 클로저 개선 주장은 실제 SLAM 재생에서 검증한다.

실행별로 데이터 및 키프레임 목록, 스키마 버전, P31 입력 해시, 좌표계와 스케일, 설정, 시간 측정 환경과 실패 사례를 보존한다.
